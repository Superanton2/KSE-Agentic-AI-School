## Контекст проєкту

Репозиторій: https://github.com/Superanton2/KSE-Agentic-AI-School (зараз порожній).
Проєкт: прогноз повітряних тривог у **Києві** («Чи встигну закупитись у Metro до тривоги»).
Дедлайн усього проєкту: пн 12.10.2026 23:59 (Київ). **На цю фазу — до 3 годин.**

Жорстка вимога ТЗ: **жодних витоків даних**. Модель у момент t може знати лише те, що було опубліковано до t.
Тому кожен запис має зберігати не тільки час події, а й час, коли ми про неї дізналися.

### Що вже перевірено (не відкривай заново, але перевір цифри у себе)

Джерело історії: https://github.com/Vadimkin/ukrainian-air-raid-sirens-dataset (MIT, оновлюється щодня).

- `datasets/official_data_en.csv`: колонки `oblast, raion, hromada, level, started_at, finished_at, source`, час у UTC.
  - **Застарів**: коміт свіжий (11.10.2026), але останній запис — 2026-09-07. Діру треба добрати з Telegram.
  - **Точні дублікати рядків**: для `Kyiv City` 4141 рядок → 2267 після `drop_duplicates()`. Імовірна причина — допис у CSV в режимі append у `processors/official_channel_processor.py` (гіпотеза, не доведено).
  - Київ завжди `oblast == "Kyiv City"`, `level == "oblast"` (сирена в місті загальноміська).
  - З грудня 2025 інші області переважно оголошуються на рівні районів (`level == "raion"`).
  - Прихована імпутація в парсері автора: якщо прийшла нова тривога для локації, де стара не закрита і минуло > 3 год, стара закривається як `started_at + 1h` без жодного прапорця. Якщо < 3 год — стара тривога просто **перезаписується (губиться)**. Тривалостей рівно 3600 с — 255 рядків на всю країну, 1 для Києва.
- `datasets/volunteer_data_en.csv` (канал eTryvoga): колонки `region, started_at, finished_at, naive`. Свіжий до 2026-10-11, тільки рівень областей. `naive=True` означає, що кінець домальований як старт + 30 хв.
- Після дедупу кількість тривог по Києву між джерелами близька (2023: 301 vs 304; 2024: 502 vs 524), а сумарні години 2025 — ні: 740 (офіційні) vs 419 (волонтерські). Це треба показати у звіті.
- Telegram-канали (перевірено в коді `processors/`):
  - офіційний: **`air_alert_ua`** — основне джерело (і для історії, і для живого колектора);
  - волонтерський eTryvoga: **`UkraineAlarmSignal`** — тільки для перехресної перевірки.
- Формати повідомлень `air_alert_ua` (з коментарів у коді автора; **перевір на реальних повідомленнях, не вигадуй**):
  ```
  🔴 16:29 Повітряна тривога в Донецька область
  #Донецька_область

  🟢 17:02 Відбій тривоги в Донецька область.
  #Донецька_область

  🟡 06:22 Відбій тривоги в Дніпропетровська область
  (тривога ще триває у якомусь районі)
  #Дніпропетровська_область

  🟢 12:33 Відбій тривоги в
  • Мелітопольський район
  • Василівський район
  ...
  #Мелітопольський_район #Василівський_район ...
  ```
  Локації беруться з **хештегів в останньому рядку** і мапляться через `processors/states.json` (+ `legacy_states.py` для перейменувань). Повідомлення з «Тестовий Регіон» ігноруються. Час події = `message.date` (UTC, час публікації), а не HH:MM з тексту.

## Мета фази

1. Перевірити й почистити готовий датасет, отримати чесний звіт якості.
2. Добрати дані з `air_alert_ua` від 2026-08-25 до зараз (з перекриттям для перевірки парсера).
3. Запустити живий колектор, який безперервно дописує нові тривоги.
4. Зібрати єдиний чистий набір тривог, з якого далі будуть будуватися фічі й мітки.

**Не входить у фазу**: теплокарта, розподіли тривалостей, будь-яке моделювання, API, фронтенд.

## Архітектура (обов'язкова)

```
Vadimkin CSV ──► validate + clean ──────────────────────────┐
                                                             ▼
Telegram air_alert_ua ──► raw_messages (SQLite) ──► parser ──► alerts (SQLite) ──► build ──► data/processed/alerts.parquet
   (backfill + live,         незмінний журнал        чиста      інтервали                    + reports/data_quality.md
    ідемпотентно)                                    функція
```

Ключові принципи:
- **Сирі повідомлення — незмінний журнал.** Інтервали тривог завжди можна перерахувати з нуля з `raw_messages`. Ніяких pickle-станів, як у вихідному репо.
- **Backfill і live — один код.** На старті live-колектор дочитує все, що пропустив (`min_id = max(msg_id)`), потім слухає нові повідомлення. Повторний запуск backfill не створює дублів (`INSERT OR IGNORE` за `(channel, msg_id)`).
- **Нічого не губимо мовчки.** Нерозпізнані повідомлення й невідомі хештеги → таблиця `parse_errors`. Аномалії стану (повторний старт без відбою, відбій без старту) → прапорці в `alerts`, а не перезапис.
- **Незакрита тривога = `finished_at IS NULL`.** Ніколи не домальовувати кінець для поточних тривог — це витік даних.

## Схеми даних

### SQLite `data/live/alerts.sqlite`

```sql
raw_messages(
  channel TEXT, msg_id INTEGER, posted_at TEXT,   -- UTC ISO, message.date
  edited_at TEXT NULL, text TEXT,
  received_at TEXT,                                -- UTC, коли ми отримали
  ingest_mode TEXT CHECK (ingest_mode IN ('backfill','live')),
  PRIMARY KEY (channel, msg_id)
);
message_edits(channel, msg_id, edited_at, old_text, new_text, received_at);
parse_errors(channel, msg_id, posted_at, reason, text);
collector_heartbeat(id INTEGER PRIMARY KEY CHECK (id=1), last_seen_at TEXT, last_msg_id INTEGER);
```

Таблиця `alerts` будується з `raw_messages` (можна перебудувати командою `rebuild-alerts`):

| колонка | тип | опис |
|---|---|---|
| `location` | str | нормалізована назва: `Kyiv City`, `Kyivska oblast`, … (як в `official_data_en.csv`) |
| `level` | str | `oblast` / `raion` / `hromada` |
| `raion`, `hromada` | str | порожні для oblast-рівня |
| `started_at` | ts UTC | `posted_at` повідомлення про старт |
| `finished_at` | ts UTC, null | `posted_at` відбою; NULL якщо триває |
| `start_known_at` | ts UTC | для live — `received_at`; для backfill/датасету — = `started_at` |
| `end_known_at` | ts UTC, null | аналогічно для кінця |
| `source` | str | `dataset_official` / `tg_official` / `dataset_volunteer` |
| `flags` | str | через кому: `dup_start`, `end_without_start`, `end_imputed`, `open_over_24h`, `naive_end` |
| `start_msg_id`, `end_msg_id` | int, null | для трасування до повідомлення |

### Політика стан-машини (на локацію)

- `start`, коли не активно → відкрити інтервал.
- `start`, коли вже активно → **не перезаписувати**; лишити ранній старт, додати прапорець `dup_start`.
- `end`, коли активно → закрити.
- `end`, коли не активно → записати в `parse_errors` з reason `end_without_start`.
- Активна > 24 год → прапорець `open_over_24h` у звіті (не закривати автоматично).
- 🟡 «Відбій … (тривога ще триває у якомусь районі)» для області = закриття oblast-рівня (районні інтервали живуть своїм життям).

### `data/processed/alerts.parquet`

Два рівні в одному файлі (колонка `granularity`):
- `raw` — інтервали як є (після дедупу);
- `oblast_union` — для кожної області об'єднання (union) усіх її інтервалів на будь-якому рівні: «є тривога десь в області». Для `Kyiv City` це те саме, що `raw`.

Шов датасет / Telegram: точка `C = 2026-09-01T00:00Z`. З датасету беремо тривоги зі `started_at < C`, з Telegram — зі `started_at >= C`. Перевірити, що на шві немає дублів і пропусків (тест).

`manifest.json`: час побудови, коміт датасету Vadimkin, `max(posted_at)` з Telegram, кількість рядків по джерелах, версія коду (git sha).

## Перевірки якості (validate.py → звіт)

Кожна перевірка має статус `PASS / WARN / FAIL`, число і короткий опис. `FAIL` = код виходу ≠ 0.

**Готовий датасет (official і volunteer окремо):**
1. Схема й типи (pandera): колонки, tz-aware UTC, `level` з допустимого набору.
2. `started_at < finished_at` для всіх закритих; нульові/від'ємні тривалості → FAIL, якщо > 0.1%.
3. Точні дублікати: кількість до/після (очікувано ~45% рядків Києва — WARN, не FAIL, бо ми їх прибираємо).
4. Перекриття інтервалів для однієї локації після дедупу → злити, показати кількість.
5. Тривалості: `< 60 с`, `> 12 год`, рівно `3600 с` (імпутація автора), рівно `1800 с` / `naive=True` (волонтерські).
6. Свіжість: `max(started_at)` по кожному джерелу і відставання від поточного часу. Official > 3 днів → WARN з поясненням.
7. Дірки покриття: дні, коли по всій Україні 0 записів (під час війни так не буває) → перелік.
8. Київ, перехресна згода official vs volunteer по місяцях: кількість тривог, сумарні години, частка стартів, що збігаються в межах ±2 хв. Топ-10 найбільших розбіжностей у звіт.

**Telegram:**
9. Перевірка парсера на перекритті 2026-08-25 … 2026-09-07: для `Kyiv City` і сусідніх областей частка тривог з датасету (після дедупу), знайдених у Telegram-версії зі стартом і кінцем у межах ±1 хв. **Ціль ≥ 95%.** Якщо нижче — зупинись і покажи мені приклади розбіжностей, не підганяй.
10. `parse_errors`: кількість і топ причин; частка нерозпізнаних повідомлень < 1%.
11. Ідемпотентність: повторний backfill не змінює кількість рядків.
12. Live-затримка: `received_at - posted_at` для live-повідомлень (медіана, p95).
13. Шов `C`: немає дубля тривоги, що почалась біля `C`.

## Тести (pytest, офлайн, без Telegram)

- Парсер на фікстурах: 🔴 область, 🟢 область, 🟡 частковий відбій, багато районів в одному повідомленні, `#м_київ` (перевір реальний хештег Києва), «Тестовий Регіон», невідомий хештег → `parse_errors`, повідомлення без тексту. Фікстури — з реальних повідомлень (збережи 20–30 справжніх у `tests/fixtures/air_alert_ua_sample.json` після першого backfill).
- Стан-машина: усі гілки політики вище.
- `clean.py`: дедуп, злиття перекриттів, union до області (hypothesis: union ніколи не має перекриттів, сумарна тривалість union ≤ суми і ≥ max).
- Шов датасет/Telegram на синтетичних даних.
- Ідемпотентність store (двічі вставили → ті самі рядки).
- Тест «без витоку»: для будь-якого рядка `start_known_at >= started_at` і `end_known_at >= finished_at`; незакриті тривоги мають `finished_at IS NULL`.

## Безпека

- Файл сесії Telethon = повний доступ до мого Telegram. Шлях з `TG_SESSION_PATH` **поза репозиторієм**, права `600`, `*.session` у `.gitignore`. Перевір `git status` перед кожним комітом.
- Колектор тільки **читає** публічні канали: жодних `send_message`, приєднань до каналів чи інших дій від мого імені.
- Ніде не логувати номер телефону, коди входу, `api_hash`.
- `FloodWaitError` → чекати вказаний час, не ретраїти агресивно.
- Docker: не-root користувач, `read_only: true` + `tmpfs` для `/tmp`, том лише для `data/live` і сесії, **жодних відкритих портів**, `restart: unless-stopped`.
- Healthcheck: `collector_heartbeat.last_seen_at` не старіший за 5 хв.
