## 1. Сітка, мітки, ознаки (таймбокс 40 хв) → `src/airalert/model/features.py`

**Сітка**: моменти прогнозу t кожні 5 хв (UTC), 2026-08-10 … now.
**Стан у t**: «тривога триває», якщо старт відомий до t (`start_known_at ≤ t`) і відбій не відомий до t. Усе — за `known_at`, не за подією.

**Мітки (лише для t, коли в Києві спокій)** — дискретний hazard:
для кожного t і кроку k = 1…24 (5-хв кроки до 120 хв) рядок `(t, k, y)`, де y = 1, якщо перший старт після t припадає на крок k; рядки після першого старту не створюються; цензура на кінці даних.
Похідні мітки для оцінки: `y_H` = старт у (t, t+H] для H ∈ {15, 30, 60, 120}.

**Ознаки (as-of t)** — одна функція `features_asof(t, sources)`, яку **той самий код** викликає і в навчанні, і в API:
- рівень тривог: кількість стартів за 6 год / 24 год / 72 год; частота за 14 днів (стартів на годину спокою); `log1p(хв від останнього відбою)`; тривалість останньої тривоги;
- час: година за Києвом (sin/cos), ніч (00–06);
- дрони з `drone_mentions` (версія повідомлення, відома на t; основне джерело `kudy_letyt`, `kpszsu` — окремими ознаками), вікна 15 і 30 хв:
  - `n_ring{30,80,150,300}` — сума `count` згадок, чия точка в кільці від центру Києва (50.4501, 30.5234);
  - `n_target_ring30` — «курсом на» місце в радіусі 30 км;
  - `n_jet_ring150`;
  - `min_dist_km` (cap 400, + індикатор «немає згадок»);
  - `kyiv_nebo_any_10m`; `missile_any_30m` (ракети/балістика будь-де в «Київщина/Київ»).

**Тест без витоку (обовʼязковий)**: для 200 випадкових t обріж усі джерела по `known_at ≤ t`, перерахуй ознаки — мають збігатися з повним прогоном побітово.

**Швидкий лифт (у звіт)**: для кожної дрон-ознаки (>0 vs =0) — P(старт ≤ 15/30/60/120 хв) на періоді навчання.

## 2. Моделі й оцінка (таймбокс 70 хв) → `src/airalert/model/{baselines,hazard,evaluate}.py`

**Моделі**:
- `B0` — константний hazard на крок (середнє по навчанню).
- `B1` — частота за 14 днів: λ = старти / години спокою за 14 днів до t; P(старт ≤ H) = 1 − e^(−λH).
- `M1a` — логістичний hazard: ознаки рівня тривог + час. Залежність від кроку k: **окрема логрегресія на кожен відрізок кроків** {1–3, 4–6, 7–12, 13–24} (дрон-ефект згасає з горизонтом — так це видно в коефіцієнтах).
- `M1b` — `M1a` + дрон-ознаки. **Аблація M1a vs M1b — головний результат проєкту.**
- L2-регуляризація, C підбирати лише на 08-10…09-12 (rolling); ваги за давністю (півперіод 14 днів); стандартизація всередині fold.

S(H | t) = Π_{k ≤ H/5} (1 − h_k), P(старт ≤ H) = 1 − S.

**Walk-forward на тесті**: для кожної доби d (Київ) у 09-13…10-11 модель навчається на моментах t, **чиє вікно мітки (t + 120 хв) закінчилось до 00:00 доби d** (purge — інакше витік через мітку), і прогнозує всі t доби d. Перенавчання щодоби.

**Метрики** для H ∈ {15, 30, 60, 120}: Brier, log loss, Brier skill score vs `B1`, калібрування (10 бінів). Довірчі інтервали — bootstrap **по днях** (1000), окремо для ΔBrier(M1b − M1a) і ΔBrier(M1b − B1).
Окремо: коефіцієнти дрон-ознак по відрізках кроків.

**Звіт** `reports/model_eval.md` + PNG (калібрування, BSS по горизонтах з CI). Чесно: якщо M1b не краща за M1a — так і написати, у продукт іде краща з двох.

**Fallback**: якщо до 19:15 walk-forward не готовий — одне розбиття (train до 09-12, test 09-13…10-11) з purge, і позначка в звіті.

## 3. Тривалість тривоги (таймбокс 20 хв) → `src/airalert/model/duration.py`

- Kaplan–Meier (lifelines) по тривогах Києва з 2026-06-01 (тривалості стабільніші за частоту; перевір це одним рядком — медіани до/після 17.08), `naive=True` → цензура на 30 хв.
- Умовна: P(відбій ≤ e + x | триває e) = 1 − S(e + x)/S(e).
- Перевірка на тесті: для тривог тесту в моменти e = 0, 10, 30 хв — калібрування P(відбій ≤ 15/30/60 хв).

## 4. Генератор сценаріїв (таймбокс 40 хв) → `src/airalert/model/scenarios.py`

Вихід — **точно** формат `GET /api/scenarios` з `docs/tasks/phase3-frontend.md`:
`{generated_at, horizon_min: 120, members: 5, scenarios: [{m, alerts: [[start_min, end_min|null], ...]}]}`.

- **Члени ансамблю**: 5 refit фінальної моделі на bootstrap по днях → `m = 0…4`, по 200 сценаріїв на члена.
- **Якщо зараз спокій**: перший старт — з hazard члена m (крок 5 хв, хвилина всередині кроку рівномірно); тривалість — з KM; наступні старти після відбою — з `B1`-частоти (експоненційно). Наближення задокументуй.
- **Якщо зараз тривога**: перший інтервал `[−elapsed, end]`, end — з умовного KM; далі як вище.
- Кінець за горизонтом → `null`. Розмір JSON ≤ 60 КБ, генерація < 1 с.
- **Паритет симулятора**: портуй `web/js/sim.js` у `src/airalert/model/sim.py` (той самий алгоритм) і спільні тестові випадки `tests/fixtures/sim_cases.json`, які проганяють і pytest, і `node --test`.

**Продуктовий бектест (головна продуктова метрика)**: 2000 випадкових поїздок у тестовому вікні (t — випадковий момент; дорога U(10, 40) хв; покупки N(60, 15) обрізане [20, 120]; очікування N ∈ {0, 15}). Для кожної: передбачене P(успіх) зі сценаріїв, згенерованих на t (walk-forward моделі доби), vs фактичний результат за справжніми тривогами. Brier, калібрування, порівняння з тим самим на `B1`-сценаріях. У звіт.

## 5. `model-card.json` і API (таймбокс 40 хв) → `src/airalert/api/app.py`

`data/processed/model_card.json`:
`{updated_at, test_period, n_test_starts, skill: {"0-30": BSS@30, "30-60": BSS@60, "60-120": BSS@120}, metrics: [...], calibration: [...], ablation: {...}, product_backtest: {...}, notes}`.
Фронтенд показує «Дуже неточно», коли `skill < 0` — тож тут ніяких округлень на користь моделі.

FastAPI:
- `GET /api/state` — з живих БД (Київ: статус, `since`, `level` з SITREP, якщо є; `data_as_of` = час останнього повідомлення колектора, а не час запиту).
- `GET /api/scenarios` — генерується у фоні кожні 30 с з **поточних** ознак (`features_asof(now)`), ETag, `Cache-Control: no-store`.
- `GET /api/model-card`, статика `web/` на `/`.
- Заголовки: CSP з phase3, `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`, `Permissions-Policy: geolocation=(self)`. Без логування query string. Bind `127.0.0.1:8000`.
- Compose: сервіс `api` у профілі `serve`, read-only, non-root, healthcheck `/api/state`.
- Нічне перенавчання (04:00) у сервісі `nightly`: rebuild → refit → model_card.
