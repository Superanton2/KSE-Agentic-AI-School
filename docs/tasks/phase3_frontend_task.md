## Що будуємо

Сайт для киянина: **«Чи встигну я доїхати в Metro, закупитись і оплатити до початку тривоги?»**
Реально його побачить переважно рецензент — він має зрозуміти все за 30 секунд без інструкцій.

Три принципи, які важливіші за будь-яку фічу:
1. **Мінімалізм.** Карта, статус, одна картка результату. Усе інше — сховане за кнопкою.
2. **Швидкість і легкість.** Без фреймворків і збірки. Бюджет: власний JS+CSS ≤ 60 КБ (без стиснення), перший рендер < 1 с на 4G, жодних зовнішніх шрифтів.
3. **Безпека даних.** Координати користувача **не надсилаються на наш сервер**. Немає аналітики, cookies, сторонніх трекерів.

Фронтенд пишемо **зараз на фейкових даних** за контрактом нижче; бекенд підключимо пізніше заміною базового URL.

## Стек і структура

- Vanilla JS (ES-модулі), без npm-залежностей у рантаймі, без збірки.
- Leaflet 1.9.4 — **завантажити в репозиторій** (`web/vendor/leaflet/`), не з CDN (швидкість + CSP + немає стороннього JS).
- Тести: `node --test` (вбудований раннер Node, нуль залежностей) для чистих модулів.
- Роздача: зараз `python -m http.server -d web 8080`; пізніше — `StaticFiles` у FastAPI (той самий origin, без CORS).

- Кольори ймовірності й кольори рівня тривоги не змішуються в одному елементі.
- Шрифт — системний стек (`system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`), цифри `font-variant-numeric: tabular-nums`.

### Карта
- Підложка CARTO `dark_nolabels` (без назв). Атрибуція OSM/CARTO дрібно в куті (обовʼязково).
- Межі районів Києва — пунктир 1px `--border`, без підписів.
- Маркери Metro — невеликі кола `--text` з обводкою; вибраний — більший, `--accent`.
- Маркер «я» — точка `--accent` з півпрозорим колом точності геолокації.
- Початковий вигляд — Київ цілком; після вибору магазину — fitBounds(я, магазин).
- Дрони на карті **не показуємо** (можливе розширення пізніше: іконка над областю без точного місця, як в alerts.in.ua).

### Компоненти головного екрана

**Мобільний (за замовчуванням)**
```
┌─────────────────────────────┐
│ ( 🟢 Спокій · 2 год 14 хв ) │  ← пігулка статусу, зверху по центру
│   дані станом на 13:42      │
│                             │
│          КАРТА              │
│     • Metro   • Metro       │
│            ◉ я              │
│                             │
│ ┌─────────────────────────┐ │  ← картка результату (bottom sheet)
│ │ Metro Теремки           │ │     з'являється після вибору магазину
│ │ 74%  Ризиковано         │ │
│ │ 80%: 66–81%             │ │
│ │ дорога 18 хв · ~60 хв   │ │
│ │ ▁▂▄▆▅▃  найкраще: 14:20 │ │  ← міні-крива «виїзд через 0…60 хв»
│ └─────────────────────────┘ │
│ ( ☰  🔍  ⚙  ◎  ⓘ )          │  ← нижня панель
└─────────────────────────────┘
```
**Ноутбук (≥ 900 px)**: та сама карта на весь екран, картка результату — плаваюча праворуч (ширина 360 px), нижня панель по центру. Без окремих макетів — один CSS з медіа-запитом.

- **Пігулка статусу**: «Спокій · 2 год 14 хв» / «Тривога · 23 хв» + іконка рівня (жовтий/червоний). Таймер тікає щосекунди локально; дані оновлюються з API.
- **Картка результату**:
  - назва магазину, велике число `74%` кольором ймовірності + слово;
  - під ним дрібно `80%: 66–81%` (інтервал між членами ансамблю, див. симулятор);
  - `дорога 18 хв · покупки ~60 хв` (якщо маршрут fallback — «≈ 18 хв, приблизно»);
  - якщо зараз тривога або висока ймовірність прибути під час тривоги: `ймовірне очікування ~25 хв (до 50 хв у 80% випадків)`;
  - міні-крива (inline SVG, без бібліотек): P(успіх) для виїзду через 0, 5, …, 60 хв; підпис «найкраще вікно: виїзд о 14:20 — 81%».
- **Стан «Дуже неточно»** (`--p-unsure`, число сіре, підпис «Дуже неточно — модель тут слабка»), коли:
  - дорога + очікування + покупки виходять за горизонт сценаріїв (120 хв), або
  - ширина інтервалу > 30 п.п., або
  - `model-card.skill[horizon_bucket] < 0` (модель на цьому горизонті не краща за базову).
- **Нижня панель**: ☰ меню (Про модель, мова — пізніше) · 🔍 пошук · ⚙ розширені налаштування · ◎ моя локація · ⓘ коротка довідка.
- **Пошук**: поле з автодоповненням — спершу фільтр по магазинах з `stores.geojson` (локально), потім адреса через Photon (`photon.komoot.io`, bbox Києва, debounce 400 мс, ≥ 3 символи). Обрана адреса = **точка відправлення**, а не магазин (магазини обираються з карти/списку).
- **Розширені налаштування** (висувна панель знизу / справа):
  - покупки: середнє 60 хв, розкид ±15 (слайдери);
  - готовий чекати відбою: 0–60 хв (за замовчуванням 0);
  - затримка відкриття після відбою: 0–30 хв (0);
  - час дороги вручну: вимкнено / N хв;
  - заклад: Metro (McDonald's — пізніше, з режимом «пішки»).
  Налаштування зберігаються в `localStorage` (у try/catch), координати — **ні**.
- **Банер тривоги**: при зміні статусу спокій→тривога — смуга зверху «Оголошено тривогу» на 10 с, без звуку й вібрації; картка перераховується.
- **Застарілість**: «дані станом на HH:MM» завжди видно. Ймовірність ховається (замість числа — «Немає свіжих даних»), якщо `now − state.data_as_of > 10 хв` **або** API не відповідає > 10 хв. Між запитами — тихий retry з backoff.

### Сторінка «Про модель» (`model.html`)

Стиль kyivsafety/methodology: вузька колонка тексту, великий заголовок, два блоки-врізки.
1. Жовта врізка: **«Це не порада з безпеки.»** Ми оцінюємо шанс встигнути з покупками, а не небезпеку. Під час тривоги — в укриття.
2. Синя врізка **«Коротко»**: формула успіху поїздки + одним абзацом, з чого складається прогноз.
3. Розділи: Дані · Що змінилось з 17.08 · Моделі · Як рахується ваш шанс · Наскільки це точно (метрики з `model-card.json`: таблиця моделей vs бейзлайни, графік калібрування inline SVG) · Обмеження · Приватність.
Цифри підставляються з `/api/model-card`, текст — у `i18n/uk.json`. Поки моделі нема — плейсхолдери «буде після оцінки», без вигаданих цифр.

## Контракт API (фіксуємо зараз)

Усі часи — ISO 8601 UTC. Бекенд віддає `Cache-Control: no-store` для state/scenarios.

`GET /api/state` (опитування кожні 15 с)
```json
{
  "status": "calm",              // calm | alert
  "level": null,                 // null | yellow | red
  "since": "2026-10-12T10:58:00Z",
  "data_as_of": "2026-10-12T11:13:40Z",
  "sources_ok": {"alerts": true, "drones": true}
}
```

`GET /api/scenarios` (опитування кожні 30 с; ETag)
```json
{
  "generated_at": "2026-10-12T11:13:30Z",
  "horizon_min": 120,
  "members": 5,
  "scenarios": [
    {"m": 0, "alerts": [[-12, 9], [47, 81]]},
    {"m": 1, "alerts": [[-12, 22]]}
  ]
}
```
- `alerts` — інтервали тривог у хвилинах від `generated_at`; поточна тривога має від'ємний старт; кінець `null` = триває за горизонтом.
- `m` — член ансамблю (0…members−1) для інтервалу невизначеності. Усього ~1000 сценаріїв (≈ 200 на члена).

`GET /api/model-card`
```json
{"updated_at": "...", "test_period": ["2026-09-13", "2026-10-11"],
 "skill": {"0-30": 0.21, "30-60": 0.09, "60-120": -0.02},
 "metrics": [...], "calibration": [...], "notes": "..."}
```

`GET /api/stores` — той самий GeoJSON, що в `web/data/stores.geojson` (можна віддавати статикою).

Фейкові файли в `web/mock/` мають покривати: спокій, тривога жовтого рівня, тривога червоного рівня, застарілі дані. Перемикач `?mock=calm|alert|stale` у URL.

## Браузерний симулятор (`js/sim.js`) — чисті функції

Вхід: `scenarios`, `elapsed_min` (= `(now − generated_at)/60000`), параметри поїздки `{depart_in, travel, shop_mean, shop_sd, wait_max, open_delay}`, `seed`.

Для кожного сценарію s (детерміновано, seed + індекс):
1. `T_s ~ Normal(shop_mean, shop_sd)`, обрізати до [20, 120].
2. `arrive = elapsed + depart_in + travel`.
3. Якщо в `arrive` триває тривога (кінець `e`): якщо `e − arrive ≤ wait_max` → `open = e + open_delay`, `wait = e − arrive`; інакше **невдача** (`wait = >wait_max`).
   Інакше `open = arrive`, `wait = 0`.
4. Якщо `open + T_s > horizon_min` → результат `beyond_horizon`.
5. **Успіх**, якщо жодна тривога не стартує в `(open, open + T_s]`.

Вихід: `p` (частка успіхів серед сценаріїв у горизонті), `p_band` (10-й і 90-й перцентилі `p` по членах ансамблю), `share_beyond`, `wait_median`, `wait_p80` (серед сценаріїв з тривогою на прибутті), `curve` (p для `depart_in` = 0, 5, …, 60) і `best` (argmax).
Перерахунок на кожну зміну параметрів — ціль < 20 мс на 1000 сценаріїв × 13 точок кривої.

Тести (`node --test`):
- без тривог у сценаріях → p = 1;
- тривога, що стартує посеред покупок → невдача;
- поточна тривога закінчується за 10 хв, `wait_max = 15` → успіх, `wait = 10`; `wait_max = 5` → невдача;
- `open_delay` зсуває вікно покупок;
- монотонність: більший `shop_mean` → p не зростає; більший `wait_max` → p не спадає;
- вихід за горизонт → `beyond_horizon`, а не успіх;
- детермінованість при фіксованому seed.

## Маршрут (`js/route.js`) — у браузері

- OSRM FOSSGIS: `https://routing.openstreetmap.de/routed-car/route/v1/driving/{lon1},{lat1};{lon2},{lat2}?overview=false` (для McDonald's пізніше — `routed-foot`).
- Таймаут 4 с. Fallback: відстань по прямій × 1.4 / 25 км/год, позначка «приблизно».
- Кеш у пам'яті за ключем (старт, округлений до ~200 м, магазин). Не запитувати частіше ніж раз на 5 с і лише коли змінились старт/магазин.
- Затори не враховано — сказати про це одним рядком у картці («без урахування заторів, можна змінити в ⚙»).

## Геолокація (`js/geo.js`)

- Запит при відкритті (`getCurrentPosition`, `enableHighAccuracy: false`, `maximumAge: 60000`, таймаут 8 с) — браузер покаже свій діалог, обійти його не можна.
- Відмова/помилка → точка в центрі Києва + підказка «Торкніться карти, щоб вказати, звідки їдете». Клік по карті переставляє точку.
- Поза межами Києва (bbox з запасом) → попередження «Сервіс рахує тривоги лише для Києва».
- Координати живуть лише в пам'яті сторінки й ідуть лише в OSRM/Photon (це сказати на сторінці «Про модель», розділ «Приватність»).

## Безпека

- CSP через `<meta http-equiv>` зараз і заголовком у FastAPI пізніше:
  `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data: https://*.basemaps.cartocdn.com; connect-src 'self' https://routing.openstreetmap.de https://photon.komoot.io; frame-ancestors 'none'; base-uri 'none'; form-action 'none'`.
- Жодних inline-скриптів і `innerHTML` з даними з мережі (лише `textContent`/створення елементів) — назви магазинів і адреси з Photon вважати недовіреними.
- `Referrer-Policy: no-referrer` (щоб OSRM/Photon не бачили наш URL), `Permissions-Policy: geolocation=(self)`.
- Жодних ключів у фронтенді.
